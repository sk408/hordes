## 2. TASK 2 — static defect audit

### 2.1 Desktop pad layer renders on top of the intro movie (real, wave-23 regression)

- `src/main.js:2681` adds the class at module load: `touchLayer.classList.add(hasTouch ? 'on' : 'cog-only')`.
- `index.html:98` then makes the whole layer visible: `#touch.cog-only { display: block; }`.
- The only thing that hides the layer on desktop is `updateTouchHud()` (`src/main.js:2820`,
  display written at `src/main.js:2823`), and `frame()` **early-returns before reaching it**
  while mode is `intro` (`src/main.js:3212`) or `portal-cine` (`src/main.js:3223`).

Net effect: for the entire ~7 s intro movie of every page load, a desktop player sees the
FOCUS/STANCE/PILOT/STATS pad, the FROST/OVER/HP/MP pad, the 14 px hints panel, the cog and
the "?" button drawn over the title art. `portal-cine` has the same hole (the layer keeps
whatever display the previous frame set).

Verified, not inferred: loaded the working tree in a real non-touch browser at
main.js `c0959c60` / index.html `994ca398`, screenshot at 03:58 shows all 8 pad buttons,
the hints panel and both corner buttons composited over the HORDES intro art, with no menu
overlay present (`#ov-cards` empty, only the 10 touch elements in the a11y tree). The
published build does not do this — it ships `#touch.cog-only .pad { display: none; }`
(see section 4), so this is introduced by the wave-23 "full layer for desktop" change.

Note the desktop refinement someone added at `index.html:107-109` (62x44 targets, pad
`opacity: 0.55`) mitigates the arena-corner overlap but does nothing for the intro, because
the intro path never runs `updateTouchHud`.

### 2.2 Auto-repeat guard is incomplete (partial fix of a real defect)

`src/main.js:2617` is the wave-23 "no auto-repeat on the held action keys" fix:

```js
if (ev.repeat && (k === 'tab' || k === 'g' || k === 'h' || k === 'n')) return;
```

It covers 4 keys. Every other edge-triggered key below it still runs on OS key-repeat:
`escape`/`p` (`src/main.js:2613`), `m` (2625), `i` (2626), `?`/`f1` (2628), `+`/`-`
(2632-2633), and `s` (2638). Holding ESC is the worst case: the repeat tick is handled by
the `settings` branch (which closes the pause), the next tick re-enters the `playing`
branch and re-opens it, so the pause flickers at the keyboard repeat rate and the run is
intermittently live. Holding M flips AUTO/MANUAL on every repeat tick; holding I or S
flips the FIELD REPORT; holding `?` strobes the hints; holding `+`/`-` walks the zoom
ladder 1→2→3→4→6→8. Not covered by any test.

### 2.3 Module state that is never reset between runs

`state.synergyNames` (`src/main.js:171`) is the toast-dedup set. `refreshSynergies()`
(`src/main.js:720-727`) computes `prev = state.synergyNames` (721) and only toasts names
not in `prev`. `startRun()` (`src/main.js:2296-2386`) clears ~30 other fields but never
touches `synergyNames`. Consequence: a synergy that was live in run N is silently not
announced at the start of run N+1. Reachable, not theoretical: `meta.js:510` gives a
character `startingWeapon: 'ORBIT'`, and the base VOLLEY is always equipped, so
VOLLEY+ORBIT ("Orbital Volley") is live at t=0 of every run with that pilot — the second
run onwards loses the announcement. Fix belongs in `startRun`, e.g. `state.synergyNames = null`.

### 2.4 Hardcoded value that contradicts CONFIG (fresh drift inside the audit window)

`src/config.js:140` now defines `RIM: 600, // arena clamp edge in world px (MUST match
main.js's ...)`. `src/render.js:1153`, `1232` and `1347` read `C.GROUND.RIM`. `main.js`
still hardcodes the literal in six places and never references the config:
`src/main.js:254`, `255`, `1151`, `1152`, `3063`, `3064`. The config comment asserts the
two must match, so any future change to `RIM` silently desyncs the drawn wall from the
simulation clamp.

### 2.5 Hardcoded magic number that duplicates (and bypasses) an exported config knob

`src/final_boss.js:58` exports `speedMult: 0.35` for `FINAL_BOSS`. Grep shows it is read
nowhere (`driftSpeedMult` at `final_boss.js:182` is the one actually used). `src/main.js:3018`
instead does `b.speed = 140;`. Related latent hazard: `makeFinalBoss()`
(`src/final_boss.js`) does not set `speed`, and `mawSpd` is derived from it at
`src/main.js:3062` (`b.speed * ...`), so deleting that hardcoded line would put the maw at
`NaN` coordinates rather than at a wrong speed — a silent, total NaN failure. The factory's
own header comment says the consumer should use the exported size/speed.

### 2.6 Two shapes for the same object; duplicated constant

`src/main.js:172` initialises `wave: { num: 1, endsAt: 120, boss, bosses, pendingClear,
startKills, cinePending }` — `endsAt: 120` hardcodes `CONFIG.ESCALATION.WAVE_LENGTH`
(config.js:262) and the literal has no `midAt` / `midBossDone` / `midBosses`, which
`startRun` adds at `src/main.js:2374`. Harmless today (only `startRun` and `continueRun`
read those fields) but it is two different shapes for one object plus a stray copy of a
tuning constant.

### 2.10 NaN / Infinity sweep (clean)
